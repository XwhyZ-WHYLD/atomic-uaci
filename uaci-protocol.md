# UACI Protocol — Field Specification

> **Version:** 1.0.0
> **Status:** Specification stage — April 2026

---

## Overview

The UACI Protocol defines the structure of the cryptographic identifier assigned to every piece of AI-generated content processed through the UACI Framework. The identifier is generated atomically at inference time by the PAIR Router and embedded alongside the content watermark and P3 Capsule.

---

## Identifier Structure

Total size: 30 bytes (240 bits)

| Field | Size | Type | Description |
|-------|------|------|-------------|
| version | 1 byte | uint8 | Protocol version — enables hash agility migration |
| timestamp_utc | 6 bytes (48 bits) | uint48 | UTC millisecond timestamp of generation |
| model_fingerprint | 8 bytes (64 bits) | BLAKE3-128 (truncated) | Fingerprint of the generating model |
| content_hash | 8 bytes (64 bits) | SHA256-128 (truncated) | Hash of the raw generated content |
| crc32 | 4 bytes (32 bits) | CRC32 | Low-cost integrity check for non-crypto errors |
| reserved | 3 bytes | — | Reserved for future extension |

---

## Hash Agility

The version byte enables migration between hash algorithms without breaking existing identifiers.

| Version | model_fingerprint | content_hash | Status |
|---------|------------------|--------------|--------|
| 0x01 | BLAKE3-128 | SHA256-128 | Current |
| 0x02 | BLAKE3-256 | SHA3-256 | Roadmap |

Default is BLAKE3-128 — chosen for performance and collision resistance at the required security level.

---

## Collision Resistance

For n identifiers generated, the collision probability under BLAKE3-128 is:

```
p ≈ n² / 2¹²⁹
```

At operational scale of n = 10⁹ (one billion assets):

```
p < 10⁻¹⁸
```

This is negligible for any foreseeable deployment scenario.

---

## CRC32

The CRC32 field provides a low-cost integrity check for detecting accidental corruption — bit flips during transmission, storage errors, and similar non-adversarial failures. It does not provide cryptographic integrity guarantees — that is the role of the P3 Capsule HMAC.

---

## Encoding

UACI identifiers are encoded as lowercase hexadecimal strings for human-readable contexts and as raw bytes for binary protocols.

**Hex representation example:**
```
01-18a7b3c2d4e5-a3f2c1b4d5e6f7a8-b1c2d3e4f5a6b7c8-d4e5f6a7-000000
```

Fields separated by hyphens for readability. Production encoding omits separators.

---

## Uniqueness Guarantees

Uniqueness is guaranteed by the combination of:
- timestamp_utc (48-bit millisecond precision — unique within any single millisecond window per model)
- model_fingerprint (identifies the generating model instance)
- content_hash (binds the identifier to the specific content)

Two identical content assets generated at the same millisecond by the same model will produce the same identifier — this is intentional and enables deduplication detection.

---

## PAIR Router Integration

The UACI Protocol identifier is generated by the PAIR Router immediately after inference, before output is released to the caller.

```
Inference completes
    ↓
PAIR Router captures raw output
    ↓
UACI ID generated (3ms median)
    ↓
StealthResist watermark embedded (42ms median)
    ↓
P3 Capsule encrypted (included in ID generation time)
    ↓
Bound output released: { uaci_id, watermarked_content, p3_capsule }
```
